# API приложений SimplyOS

Актуально для App API 1.10 в SimplyOS 26.10-Dev.73 и новее. Идентификатор сеанса окна и отдельный канал ответа появились в Dev.59; API 1.9 добавляет управление зарегистрированной фоновой службой. [Машинный контракт](api-contract.json) фиксирует методы, разрешения и допустимые фоновые службы. Он описывает политику доступа, но не является кодом, который её применяет. Версия API отличается от номера обновления ОС и от `formatVersion` пакета. Приложение обращается к API через `window.simplyos.request(method, payload)`. Мост внедряется в HTML установленного приложения при открытии; его нельзя подключить обычным `<script>` с сайта.

## Создание пакета

VPK — ZIP-архив с расширением `.vpk`. В его корне должны находиться `manifest.json` и HTML-файл из поля `entry`; дополнительные JS, CSS и изображения кладутся внутрь архива. Пример структуры:

```text
manifest.json
index.html
app.js
icons/app.svg
```

Обязательные поля манифеста: `format: "vole-app"`, `formatVersion: 1`, `id`, `name`. Рекомендуется явно задавать `appVersion`, `entry` и `permissions`; если они отсутствуют, используются соответственно `0.0.0`, `index.html` и пустой список. Необязательные поля: `developer`, `icon`, `networkHosts`. ID содержит строчные латинские буквы, цифры, точки и дефисы, от 3 до 80 символов. `permissions` содержит имена разрешений из контракта, а не имена всех вызываемых методов. В `networkHosts` перечисляются точные домены или узлы с портами для сетевого API, не более 20 записей. Лимиты архива: 50 МБ при загрузке, 200 МБ распакованных данных, 2 000 файлов. Произвольные установочные скрипты в VPK не выполняются.

```json
{
  "format": "vole-app",
  "formatVersion": 1,
  "id": "org.example.notes",
  "name": "Заметки",
  "developer": "Example Studio",
  "appVersion": "1.0.0",
  "entry": "index.html",
  "permissions": ["files.open", "files.save"]
}
```

Официальный Магазин проверяет подпись каталога и SHA-256 пакета. Эти проверки подтверждают происхождение и целостность пакета. Доверенный статус и заявленные разрешения выдаются отдельно. Для файла из неизвестного источника доверие можно назначить после 24 часов и действия пользователя.

Минимальный `index.html` для проверки подключения:

```html
<!doctype html>
<html lang="ru">
<meta charset="utf-8">
<title>Заметки</title>
<button id="check">Проверить API</button>
<output id="result"></output>
<script>
document.querySelector('#check').onclick = async () => {
  const result = document.querySelector('#result');
  if (!window.simplyos) {
    result.textContent = 'Системный API недоступен: проверьте доверие приложения';
    return;
  }
  try {
    const info = await window.simplyos.request('system.api.info');
    result.textContent = `API ${info.apiVersion}; доступно методов: ${info.methods.length}`;
  } catch (error) {
    result.textContent = `${error.code || 'UNAVAILABLE'}: ${error.message}`;
  }
};
</script>
</html>
```

Соберите архив так, чтобы `manifest.json` и `index.html` находились непосредственно в его корне, и присвойте архиву расширение `.vpk`. Проверяйте нужные методы по `info.methods` при запуске: наличие кода приложения не означает, что на устройстве установлена подходящая версия API или пользователем выдано разрешение.

## Кому доступны методы

| Среда | Доступ |
| --- | --- |
| Встроенная оболочка SimplyOS | Внутренние HTTP API backend после входа пользователя; это отдельный интерфейс, не мост VPK. |
| Доверенное установленное VPK-приложение | Только методы, разрешения которых перечислены в `manifest.json` и не отозваны в настройках. `system.api.info` доступен без отдельного разрешения. |
| Недоверенное VPK-приложение | Мост `window.simplyos` отсутствует. Прямой доступ к внутренним HTTP API не является поддерживаемым способом интеграции. |
| Обычный веб-сайт в браузере | Системный API приложений не предоставляется. Сайт может использовать только стандартные возможности браузера и пользовательский выбор файлов. |

Официальная подпись магазина подтверждает происхождение пакета, но сама по себе не выдаёт доверие. При установке пользователь выбирает доверие; для стороннего пакета, установленного из файла, доверие можно выдать после 24 часов и отдельного действия пользователя. Отзыв разрешений применяется при следующем запросе. Окно приложения должно оставаться открытым. В свёрнутом окне доступен ограниченный набор методов: сведения об API, уведомления, сетевые запросы, операции с уже начатым медиа-сеансом, состояние VPN и чтение состояния радиоустройства и сообщений. Остальные запросы отклоняются. API не предоставляет терминал, произвольные команды, root-доступ или прямой путь к домашнему каталогу.

## Как проверяются права

Встроенный в приложение `window.simplyos.request()` отправляет сообщение оболочке. Его локальный список известных методов служит для проверки ошибок разработчика, а не для защиты системы: приложение может сформировать сообщение самостоятельно. Решение о доступе принимает обработчик оболочки после получения сообщения.

Обработчик принимает запрос только по каналу `simplyos-app-api` от `iframe` установленного приложения с изолированным (`null`) источником. При открытии окна оболочка создаёт случайный идентификатор сеанса. Запрос должен содержать идентификатор именно этого окна и отдельный переносимый `MessagePort` для ответа. Обработчик находит окно по фактическому `event.source === iframe.contentWindow` и берёт идентификатор приложения из собственного состояния окна. Поля `appId`, `trust` и `permissions` в присланном `payload` не используются для определения прав. Затем обработчик сверяет установленный каталог приложений, доверенный статус, метод в контракте, разрешение в манифесте и список разрешений, отозванных пользователем. Перед выполнением каждой операции проверяются её параметры. Упрощённо порядок выглядит так:

```text
frame = найти установленный iframe по event.source
app = найти приложение по идентификатору окна frame
если источник или окно недопустимы — отклонить
если идентификатор сеанса не совпал или нет порта ответа — отклонить
если app.trust != "trusted" — отклонить
permission = contract.methods[method].permission
если метода нет — отклонить
если permission требуется и не указан в app.permissions — отклонить
если permission требуется и отозван пользователем — отклонить
проверить payload для выбранного метода и выполнить операцию
```

Например, `files.open` открывает системный выбор файла: приложение не может указать путь в `payload` и получить файл без выбора пользователя. Для `network.http.request` backend повторно читает установленный манифест и отозванные разрешения, проверяет `networkHosts`, адрес назначения, HTTP-метод, заголовки и размер ответа. Эти дополнительные проверки относятся к сетевому посреднику; не следует считать, что каждый метод API имеет одинаковую повторную проверку на backend.

Смена документа внутри `iframe` не передаёт новому документу порт уже начатого запроса. При повторной загрузке `iframe` оболочка прекращает действие идентификатора сеанса; для продолжения работы приложение нужно открыть заново. Такой же принцип применяется к выбору файлов через обычный HTML-элемент `<input type="file">`. Случайный идентификатор защищён от передачи через HTTP `Referer` политикой `no-referrer`. Он не заменяет проверки доверия, разрешений и параметров. Код, который выполняется внутри уже доверенного документа приложения, может обращаться к разрешённым этому приложению методам; разработчику не следует включать в него непроверенные скрипты. Проверка реализации не заменяет полноценное испытание безопасности.

## Магазин и локальная установка

| Свойство | Из Магазина SimplyOS | Из локального VPK |
| --- | --- | --- |
| Проверка происхождения | Подпись каталога, идентификатор и версия, размер и SHA-256 пакета | Подпись каталога Магазина не применяется |
| `installSource` в установленном манифесте | `official` | `unknown` |
| Начальное доверие | По выбору пользователя при установке | Недоверенное |
| Возможность доверить позже | Доступна пользователю | Через 24 часа после установки и действие вошедшего пользователя |
| Методы App API после получения доверия | По заявленным и не отозванным разрешениям | По заявленным и не отозванным разрешениям |

`installSource`, `trust` и время, после которого можно назначить доверие, записывает система при установке. Значения этих полей внутри VPK не дают приложению официального происхождения или доверия. Обновление через Магазин допускается для ранее установленного из него приложения; установка некоторых комплектных системных компонентов также привязана к проверенному пакету Магазина.

Обычные методы App API доступны по доверенному статусу и разрешениям независимо от источника установки. Исключение в API 1.9 — методы `background.status` и `background.stop`: они требуют собственной фоновой службы, зарегистрированной в системе. В [машинном контракте](api-contract.json) это отмечено полем `requiresBackgroundService`; раздел `backgroundServices` указывает конкретные разрешённые пары службы и официального приложения. Одной записи `backgroundService` в стороннем VPK недостаточно для установки или запуска службы.

## Радиоустройства Meshtastic и MeshCore

API 1.8 предоставляет высокоуровневые операции без произвольного доступа приложения к последовательному порту или Bluetooth-сокету. Для чтения нужны `mesh.read`, для подключения, отправки и записи настроек — `mesh.control`. Подключаться можно к перечисленному USB/COM-порту, Bluetooth-адресу устройства или к IP-адресу в частной локальной сети. Для IP используются TCP 4403 у Meshtastic и TCP 4000 у MeshCore. Подключение и запись настроек требуют подтверждения пользователя в SimplyOS. Устройство должно быть доступно пользователю оболочки; при установке обновления он добавляется в группу `dialout`.

```json
{
  "id": "ru.example.radio",
  "permissions": ["mesh.read", "mesh.control", "notifications.post"]
}
```

```js
const radio = window.simplyos;
const available = await radio.request('mesh.devices.list');
const port = available.serial[0]?.path;
if (port) {
  await radio.request('mesh.connect', {
    protocol: 'meshtastic', transport: 'usb', address: port
  });
  const {nodes} = await radio.request('mesh.nodes');
  const {messages, lastSeq} = await radio.request('mesh.messages', {after: 0});
  console.log(nodes.length, messages.length, lastSeq);
  // Отправлять сообщение следует только после явного действия пользователя:
  // await radio.request('mesh.send', {text: 'Привет', target: '', channel: 0});
  await radio.request('mesh.disconnect');
}
```

`mesh.status` возвращает `{connected, protocol, transport, address, lastSeq}`; при отсутствии устройства — `{connected: false}`. `mesh.messages` принимает `after` и отдаёт новые события текущего сеанса (не более 100 за запрос). Приложение может сохранять историю в `app.data`. Для Meshtastic личный адрес имеет вид `!a1b2c3d4`, пустой `target` обозначает канал. Для MeshCore личный адрес — публичный ключ контакта из `mesh.nodes`. `mesh.configure` принимает заполненные поля `name`, `shortName`, `txPower`, `region`, `preset`; последние три настройки частично зависят от протокола. При свёрнутом окне можно опрашивать только `mesh.status` и `mesh.messages`, чтобы показать системное уведомление о новом сообщении.

## Сведения об оборудовании

Метод `system.hardware.read` доступен доверенному VPK, если в манифесте указано разрешение `system.hardware.read`. Он возвращает объект `{cpuModel, graphicsModel, ramGiB}`: строковое название процессора, строковое название графического адаптера и целое число гигабайт оперативной памяти. Если `lspci` недоступен, название графического адаптера определяется по локальному каталогу PCI ID; числовые идентификаторы показываются только для устройства, которого нет в каталоге. Если оборудование определить не удалось, возвращается «Не определён» или `0` для памяти. Имя компьютера, имя пользователя, серийные номера и MAC-адреса в ответ не входят.

```js
const hardware = await window.simplyos.request('system.hardware.read');
console.log(hardware.cpuModel, hardware.graphicsModel, hardware.ramGiB);
```

Получение сведений локально не означает согласия на их передачу. Перед отправкой результатов во внешний сервис приложение должно показать точный состав данных и получить отдельное согласие пользователя. Разрешение можно отозвать в настройках SimplyOS.

## Уведомления и работа в свёрнутом окне

Приложение остаётся запущенным после сворачивания. Для почты и мессенджера можно периодически вызывать `network.http.request` и при появлении события отправлять `notifications.post`. В свёрнутом окне также доступны `vpn.status` и `background.status`. Chromium может замедлять фоновые таймеры, поэтому интервал доставки не гарантирован. Закрытое окно не выполняет JavaScript приложения. Нажатие на уведомление раскрывает окно. После выхода из учётной записи опрос из окна прекращается.

```js
async function checkInbox() {
  const response = await window.simplyos.request('network.http.request', {
    url: 'https://mail.example.org/api/unread', method: 'GET',
    headers: {Authorization: 'Bearer ' + accessToken}
  });
  if (response.status === 200) {
    const inbox = JSON.parse(response.body);
    if (inbox.newCount) await window.simplyos.request('notifications.post', {
      title: 'Новая почта', message: `Новых сообщений: ${inbox.newCount}`
    });
  }
}
setInterval(checkInbox, 30000);
```

Для такого приложения в манифесте нужны `"permissions":["network.http","notifications.post"]` и `"networkHosts":["mail.example.org"]`. Сетевой посредник не передаёт cookies пользователя, не следует перенаправлениям, ограничивает ответ 1 МБ и принимает только перечисленные узлы. Текущий мост принимает адреса HTTPS, в том числе для `network.http.private.request` к серверу локальной сети с отдельным разрешением; адреса localhost, link-local и служебных сетей закрыты. Это контролируемый обход CORS для доверенного приложения, а не отключение CORS в Chromium. Сетевые запросы ограничены 60 в минуту на приложение.

## Фоновая служба после закрытия окна

Для работы после закрытия окна приложению нужна отдельная служба, управляемая SimplyOS. Закрытие HTML-окна завершает его JavaScript, но зарегистрированная служба продолжает работу независимо от окна и может запускаться при загрузке устройства. Оболочка получает состояние службы с backend и показывает активную службу в центре уведомлений и быстрых настройках. Из этих мест можно открыть приложение или остановить службу; для остановки VPN запрашивается пароль Linux. Очистка обычных уведомлений не скрывает карточку работающей службы.

Служба не создаётся вызовом `window.simplyos.request()` и не запускает произвольный скрипт VPK в фоне. Её исполняемые файлы, настройки безопасности и системный адаптер должны поставляться проверенным пакетом Магазина и поддерживаться ОС. В API 1.9 зарегистрирована служба `vpn` приложения `ru.simplyos.vpn`. При установке сервер самостоятельно записывает `installSource: "official"`; локальный VPK с тем же полем или идентификатором службы не получает право на фоновый процесс. Для другого приложения потребуется добавить и проверить его адаптер в SimplyOS.

SimplyVPN включает в подписанный пакет движок и systemd-службу и объявляет `"backgroundService":"vpn"` вместе с разрешениями `background.read` и `background.control`. Подключение запускается методом `vpn.connect` с профилем и паролем. После закрытия окна туннель сохраняется; `background.status` возвращает `{id, appId, name, available, active, error, canStop}` для своей службы. `background.stop` требует подтверждения в SimplyOS и пароля Linux. Разрешения можно отозвать в настройках приложения; при этом пользователь по-прежнему может остановить службу через системные быстрые настройки.

```js
const service = await window.simplyos.request('background.status');
if (service.active) console.log('VPN работает после закрытия окна');
// По действию пользователя: SimplyOS покажет подтверждение и запросит пароль.
// await window.simplyos.request('background.stop');
```

## Камера и микрофон

Для доверенного VPK с разрешением `media.capture` вызовите `window.simplyos.getUserMedia({video:true,audio:true})`. SimplyOS покажет своё окно подтверждения. Поток передаётся из оболочки в изолированное приложение через локальный WebRTC-канал и работает, пока окно свёрнуто. После завершения вызова освободите устройства:

```js
const stream = await window.simplyos.getUserMedia({video:true,audio:true});
video.srcObject = stream;
// После звонка:
await window.simplyos.releaseMedia(stream);
```

Вызов `getUserMedia` запрашивает новый доступ каждый раз. Индикатор камеры и микрофона в центре уведомлений показывает активный захват. При закрытии окна SimplyOS останавливает поток. Обычные сайты и PWA в браузере используют веб-метод `navigator.mediaDevices.getUserMedia` и существующее системное подтверждение сайта.

## Bluetooth и USB

`devices.bluetooth.list` возвращает обнаруженные устройства. `connect` и `disconnect` принимают `{address:'AA:BB:CC:DD:EE:FF'}`; устройство сначала нужно сопрячь в настройках SimplyOS. Система запрашивает подтверждение и пароль Linux сама, приложение пароль не получает. `devices.usb.list` возвращает имя, идентификаторы производителя и продукта подключённых устройств. Сканер в режиме USB HID «клавиатура» передаёт штрихкод как обычный ввод в поле приложения. Прямой обмен с произвольными USB-устройствами этим API не предоставляется; для него потребуется отдельный протокол и модель доступа к конкретному классу устройств.

## Примеры

```json
{
  "format": "vole-app",
  "formatVersion": 1,
  "id": "org.example.notes",
  "name": "Заметки",
  "appVersion": "1.0.0",
  "entry": "index.html",
  "permissions": ["app.data.read", "app.data.write", "files.open", "files.save"]
}
```

```js
async function loadNotes() {
  const info = await window.simplyos.request('system.api.info');
  if (!info.methods.includes('app.data.read')) throw new Error('Доступ к данным отозван');
  const saved = await window.simplyos.request('app.data.read');
  return JSON.parse(saved.content || '{}');
}

async function storeNotes(notes) {
  await window.simplyos.request('app.data.write', JSON.stringify(notes));
}
```

```js
const selected = await window.simplyos.request('files.open', {extensions: ['.txt']});
if (!selected.cancelled) {
  const content = new TextDecoder().decode(selected.buffer);
  const saved = await window.simplyos.request('files.save', {
    name: 'Заметка.txt', content
  });
  if (!saved.cancelled) console.log(saved.path);
}
```

```js
try {
  const status = await window.simplyos.request('vpn.status');
  console.log(status.active);
} catch (error) {
  console.error(error.code, error.message);
}
```

Для двоичного `files.save` передавайте `{name:'Файл.docx', encoding:'base64', content:'...'}`. Для `printing.submit` передавайте `{name, mime, data}` с `Blob`, `ArrayBuffer` или `Uint8Array`. Пароль для `vpn.connect` и `vpn.disconnect` запрашивайте при каждом действии и не сохраняйте в `app.data`.

Отклонённый запрос возвращает исключение с полями `code` и `message`. Основные коды: `PERMISSION_DENIED`, `INVALID_REQUEST`, `METHOD_NOT_FOUND`, `FILE_TOO_LARGE`, `CONFLICT`, `UNAVAILABLE`, `TIMEOUT`. Проверяйте `code`; текст `message` предназначен для пользователя и может меняться.

## Переносимые рабочие пространства (API 1.10)

Приложение может участвовать в сохранении рабочего пространства, если его манифест содержит разрешение `workspace.state`. Метод `workspace.state.save` запоминает состояние конкретного окна; `workspace.state.load` возвращает его после повторного открытия этого окна. Оба метода доступны только доверенному приложению с действующим разрешением. Состояние ограничено 64 КБ и должно состоять из JSON-совместимых значений. Не передавайте пароли, токены, cookie, ключи или действующие соединения. SimplyOS отклоняет поля с такими именами и не включает приложение VPN в снимок.

```json
{"permissions": ["workspace.state"]}
```

```js
async function rememberWorkspace() {
  await window.simplyos.request('workspace.state.save', {
    documentPath: currentDocumentPath,
    selectedPage: currentPage,
    sidebarOpen: true
  });
}

async function restoreWorkspace() {
  const {state} = await window.simplyos.request('workspace.state.load');
  if (!state) return;
  await openDocument(state.documentPath);
  showPage(state.selectedPage);
}
```

Вызывайте `save` при изменении открытого документа или вида, а `load` при запуске. Система сохраняет состояние вместе с набором окон. Встроенный браузер и встроенные редакторы используют тот же механизм снимка через оболочку. В переносимый файл `.sws` входят открытые документы поддерживаемых форматов, а также адреса вкладок без параметров запроса и фрагментов URL. Файл шифруется AES-256-GCM с ключом, полученным из пароля пользователя через PBKDF2-SHA256; пароль не передаётся системному серверу. Импортированные документы помещаются в отдельную папку `Документы/Imported Workspaces` пользователя. Если приложение не установлено на другом компьютере, его окно пропускается при восстановлении.
