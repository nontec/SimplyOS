# Модель доступа и безопасности приложений

Сверено с SimplyOS 26.11-Release.26 и App API 1.19, 9 ноября 2026 года. Подпись каталога подтверждает происхождение и целостность пакета; доверие, разрешения и согласие на конкретную операцию проверяются отдельно.

## Типы компонентов

| Компонент | Доступ |
| --- | --- |
| Встроенная оболочка | Внутренние интерфейсы backend и предусмотренные системные операции; это не публичный App API |
| Доверенный VPK | Мост `window.simplyos`, методы из установленного манифеста и не отозванных разрешений |
| Недоверенный VPK | Ограниченное HTML-окно без системного моста; явный выбор файлов не даёт произвольного доступа к диску |
| Сайт Chromium | Отдельная гостевая страница с веб-разрешениями; не получает Node.js и мост VPK |
| Python-компонент приложения | Отдельный ограниченный исполнитель запросов, без права объявить произвольную root-службу |

Установка из Магазина фиксирует `installSource: official`; доверие выбирает пользователь. Пакет из файла получает `unknown` и недоверенный статус. Доверить его можно отдельным действием после предусмотренной задержки 24 часа. Поля внутри самого VPK не могут присвоить официальное происхождение или системные полномочия.

## Кто принимает решение

Мост отправляет запрос оболочке по выделенному каналу. Оболочка сопоставляет фактический `event.source` с iframe приложения, capability текущего документа и отдельный MessagePort ответа. Идентификатор и права берутся из собственного состояния окна и установленного каталога, не из присланных `payload.appId`, `trust` или `permissions`.

Проверяются наличие метода в контракте, доверенный статус, разрешение манифеста, отзыв пользователем, активность окна для соответствующего метода и параметры. При перезагрузке iframe старый capability перестаёт действовать; ответ не передаётся новому документу. Для чувствительных серверных функций дополнительно проверяются установленный манифест, владелец, цель и ограничения операции. Не каждый метод имеет одинаковую серверную проверку: её описание находится в [API](API.md).

Контракт JSON не является механизмом принуждения: проверки реализованы в обработчике оболочки, backend и привилегированном посреднике. Встроенные HTTP-маршруты не должны использоваться VPK для обхода моста. Защита зависит от реализации и проверок, а не от названия разрешения.

## Устройства, сеть и медиа

Каналы COM, BLE GATT, USB и сети принадлежат выдавшему их приложению/сеансу. Разрешение общего типа не даёт произвольного доступа к любой цели. Действуют выбор устройства, согласие пользователя, ограничения интерфейсов, DNS/адресов и размеров. Тома и форматирование обслуживает `devices.storage.*`; USB API не выдаёт произвольную блочную запись. [Универсальные каналы](UNIVERSAL-IO.md) · [Накопители](STORAGE.md).

Медиасогласие сохраняется отдельно от `app.data` для пользователя, приложения и типов устройств. Отзыв прекращает захват и сбрасывает согласие. Веб-клиенту дополнительно нужны актуальные разрешения приложения: кэш согласия Chromium их не заменяет. В Release.26 отзыв медиадоступа перезагружает гостевое окно для прекращения потоков, сохраняя профиль входа. Недоступная проверка политики не разрешает новый доступ.

## Фоновые режимы

Сворачивание, перенос окна в трей и отдельная системная служба различаются. `background.window` сохраняет HTML-окно, но не переживает завершение сеанса/перезагрузку. Ограниченный список методов доступен свёрнутым окнам; фоновые таймеры могут замедляться.

`background.status/stop` обслуживают только зарегистрированную собственную службу. Текущий контракт регистрирует VPN и torrent для соответствующих официальных приложений. Запись в произвольном VPK не создаёт службу. Административные операции используют фиксированные помощники и PAM-подтверждение там, где это предусмотрено.

## Данные и пределы модели

Файловые пути ограничены областью вошедшего пользователя и явно разрешёнными подключёнными носителями. Буфер обмена, устройства, сеть и данные приложения имеют отдельные права. Linux-пароль для административного действия не должен сохраняться приложением.

Почтовые реквизиты хранятся в AES-GCM-конверте; ключ получается из пароля входа через scrypt после PAM-проверки. При обычной смене пароля предусмотрен перенос конверта; после административного сброса может понадобиться повторное подключение почты. Это не шифрование всего диска, swap или ранее созданных копий.

HTML-песочница не является независимым Linux-контейнером для произвольного нативного кода. Процессы одной учётной записи и внешние программы требуют собственной оценки угроз. Обновление не включает автоматически LUKS и Secure Boot. Результат [инженерного аудита Release.26](https://simplyos.ru/security/) относится к указанным сценариям и не является сертификацией или гарантией отсутствия неизвестных уязвимостей.
