# Исправления безопасности в 26.11-Dev.21

Dev.21 устраняет обнаруженные недостатки прав браузерного runtime, изоляции пользовательских SVG, состояния проверки Debian-пакетов и хранения почтовых подключений.

- Electron заново устанавливается из проверенного архива, с правами, заданными установщиком. Исправляются уже существующие установки, а не только новые.
- Подписанный пакет ОС содержит offline-исправления APT, Chromium, ядра, libevent и zlib. Проверяются хеши, метаданные пакетов и зависимости; удаление программ не разрешено. Более новые версии не понижаются. Для DKMS приложены заголовки ядра.
- Центр обновлений показывает отсутствие пригодных индексов как незавершённую проверку, а не как отсутствие обновлений.
- SVG, загруженный через файловый просмотрщик, не получает возможность выполнять скрипты в origin оболочки.
- Почтовые подключения сохраняются в AES-256-GCM-конверте. scrypt получает ключ из пароля входа после PAM-проверки. Отдельный открытый файл с ключом не создаётся. Обычная смена пароля учитывает перенос хранилища; при административном сбросе может понадобиться переподключение почты.
- Новые внешние копии получают закрытые POSIX-права. Перед экспортом сообщается, что архив не зашифрован. На FAT/exFAT права не заменяют шифрование носителя.
- Обновлён pip системного окружения Python.

Ядро устанавливается при применении обновления. После этого нужна ещё одна перезагрузка для запуска нового ядра. Это обновление не шифрует существующий диск и ранее созданные резервные копии. Шифрование почтового файла не заменяет LUKS и не удаляет данные из старых копий, swap или свободных блоков носителя.

Проверки включали Linux-регрессии, повторную SVG-пробу в Chromium, проверку зависимостей DEB без удаления программ и полную offline-установку Python-окружения на Python 3.13. Загрузка нового ядра на всех моделях оборудования не проверялась.

App API остаётся версии 1.19. Приложениям не добавляются новые разрешения; пользовательские активные документы следует открывать изолированно от origin оболочки.

## Дополнение в Dev.23

Исправлен состав offline-набора: добавлен DEB libminizip1t64, который выбирался планом APT на исходном состоянии установочной среды. Удалённые индексы больше не влияют на этот этап установки. Помимо разрешения зависимостей проверяется доступность всех архивов через `--download-only --no-download` перед запуском dpkg. При ошибке сохраняется локальный журнал с правами 0600.

На изолированной копии базы пакетов установочной среды старый набор воспроизвёл код APT 100, исправленный — прошёл с кодом 0 без скачивания и удаления пакетов. Это проверка плана и наличия DEB, а не полная установка в пользовательской виртуальной машине.

## Дополнение в Dev.24

На существующей ВМ воспроизведён отказ реальной установки Dev.23 поверх Release.16: предварительная проверка DEB проходила, но APT 3.0 завершался ошибкой `Pathname to install is not absolute`. Теперь проверенные рабочие копии DEB имеют абсолютные пути и подготовленный частный кеш APT. Подписи и SHA-256 продолжают проверяться, загрузки и удаление пакетов на этом этапе запрещены.

Полная установка подписанного кандидата Dev.24 поверх Release.16 в VirtualBox завершилась с кодом 0. Установлены APT 3.0.4, Chromium 156.0.8078.79, новое ядро и исправленные библиотеки. После повторной перезагрузки запущено ядро 6.12.115+deb13.1-amd64, работают оболочка Electron, системные службы и backend, `dpkg --audit` не сообщает проблем. Испытанный USP опубликован без пересборки. Эта проверка не означает совместимость со всеми моделями оборудования.
