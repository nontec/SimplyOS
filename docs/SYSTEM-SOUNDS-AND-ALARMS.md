# Системные звуки и будильники

Реализация: 26.11-Dev.11. Набор сигналов синтезирован для SimplyOS без сторонних аудиозаписей. Исходный генератор хранится в `deploy/sounds/generate.py`, готовые WAV — рядом с ним.

В разделе «Настройки → Звук» системная громкость задаётся в процентах от основной. Значение 100% означает отсутствие дополнительного ослабления, а не увеличение основной громкости. Основное отключение звука и нулевая громкость выхода заглушают также уведомления и будильники. Настройка системной громкости и её выключатель сохраняются отдельно для каждого пользователя.

Звуки приложений проходят через штатные уведомления SimplyOS. Режим «Не беспокоить» убирает звук и всплывающие баннеры обычных уведомлений, сохраняя сообщения в центре уведомлений. Приложению не требуется самостоятельный аудиопроигрыватель для уведомлений. Существующий публичный метод `notifications.post` сохраняется; прямое управление службой системных звуков сторонним приложениям не предоставляется.

Будильники и таймер обслуживает поток `simplyos-clock` локального backend, запускаемый и останавливаемый вместе со службой. Он не зависит от открытого окна «Часов» и не создаёт записи в трее. Расписание, выбор мелодии и факты срабатывания сохраняются в `~/.config/simplyos/clock-sounds.json` атомарной заменой с правами 0600. Пользовательские службы backend запускаются штатным механизмом ОС; после перезапуска службы или загрузки компьютера расписание читается с диска. Чужой профиль не используется.

Событие сохраняется до начала воспроизведения, чтобы перезапуск не создавал второй экземпляр срабатывания. Сигнал повторяется до остановки. Постоянное уведомление содержит кнопку «Остановить»; закрытие этого уведомления также останавливает сигнал. Остановить активный сигнал можно из «Часов». Режим «Не беспокоить» не блокирует будильники, но основное отключение звука действует. При выключенном компьютере или глубоком сне сигнал не воспроизводится: функция пробуждения по RTC в этой реализации не добавлена. При возобновлении работы задержка до пяти минут допускает срабатывание; более старое событие показывается как пропущенное без запоздалого звукового сигнала.

Воспроизведение выполняется ограниченным действием брокера `system_sound`. Брокер сверяет UID вызывающего процесса с активной Linux-учётной записью, принимает только имя сигнала из фиксированного списка и громкость 0–100. Произвольные пути, команды и URL не принимаются. Для вывода используется `pw-play` и сеанс PipeWire оболочки; настройка потока не изменяет громкость выхода. Брокер ограничивает частоту сигналов, исключает наложение и отдаёт приоритет будильнику.

Внутренние маршруты оболочки (не самостоятельные разрешения для VPK):

| Маршрут | Назначение |
| --- | --- |
| GET/POST `/api/system/sounds` | Сохранённые `volume`, `enabled`, `dnd` |
| POST `/api/system/sounds/play` | Прослушивание фиксированного сигнала `{name}` |
| GET `/api/system/clock` | Расписание, таймер и события |
| POST `/api/system/clock/alarms` | Проверяемый список `{alarms}` |
| POST `/api/system/clock/timer` | Состояние таймера |
| POST `/api/system/clock/events/{id}/dismiss` | Остановка и скрытие события |

Маршруты требуют действующего пользовательского сеанса; изменяющие запросы дополнительно проверяют Origin. Расписание старых «Часов» однократно переносится из пользовательского хранилища интерфейса. Само воспроизведение будильника не зависит от наличия HTTP-запросов от окна.

Проверки: перезапуск планировщика, сохранение одноразового срабатывания, повтор сигнала без дублирования события, пропущенные события, остановка из уведомления, таймер без окна, режим «Не беспокоить», нулевая громкость, ограничение коэффициента усиления, проверки пользователя и Origin.
